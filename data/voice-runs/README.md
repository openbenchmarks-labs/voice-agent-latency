# voice agent latency — per-call audit trail

Everything the benchmark needs for **full third-party reproducibility** lives in this folder. Each file here is generated by `tools/export_snapshot.py` and is committed alongside the snapshot in `data/latest-voice.json`.

There is no audio in this folder and there never will be. The carrier's stereo tape for every call is served from public object storage and referenced by URL plus `sha256` — see [What is not here](#what-is-not-here).

## Layout

```
data/voice-runs/
└── <run_id>/                    # e.g. bench-telnyx-20260731-152959
    ├── bench.json               # the run's report — aggregates, receipts, honesty block
    └── call-NNN.json            # one per call — every turn, with the tape it was measured from
```

A `run_id` is `bench-<vendor>-YYYYMMDD-HHMMSS`, so it names the platform and pins the moment. `NNN` is the call index within the run. A call that failed before producing a tape has no `call-NNN.json` at all — which is why a 10-call run can export 9 files, and why the run's own `attempts` and `usable` counts are the honest denominators rather than the file count.

## Artifact format — `call-NNN.json`

Four blocks. `result` is the measurement, `metadata` is what was said and how, `recording` is the evidence, `cost` is what the platform charged.

```json
{
  "result": {
    "call_id": "call-003",
    "run_id": "bench-vapi-20260730-183425",
    "analyzer_version": "2.4.0",      // pins what "the same number" means
    "mode": "scripted_dialog",
    "rate": 8000,                      // the analyzer's working rate, after resample
    "noise_floor_dbfs": -61.5,
    "discard_reason": null,            // whole-call failure, or null
    "turns": [
      {
        "index": 2,
        "t1_ms": 17218.0,              // OUR speech ends — offset into the recording
        "t2_ms": 18966.0,              // THEIR audio starts
        "ttfab_onset_ms": 1748.0,      // t2 - t1. THE headline number.
        "ttfab_content_ms": 1748.0,    // to the first >=400ms of sustained speech
        "vendor_response_duration_ms": 994.0,
        "vad_disagreement_ms": 6.0,          // how far the cross-check detector differed
        "vad_disagreement_signed_ms": 6.0,   // sign matters: ours-earlier is the risky side
        "stimulus_start_ms": 15452.0,
        "discard_reason": null,        // per-turn, independent of the call
        "flags": ["t1_crosscheck=2.0ms", "case=cancellation-fee", "answer_verified"]
      }
      // … one per turn, 4 per call
    ]
  },

  "metadata": {
    "vendor": "vapi",
    "carrier": "plivo",
    "channel_map": { "near": 1, "far": 0 },   // WHICH CHANNEL IS WHOSE — see below
    "mode": "scripted_dialog",
    "vendor_config_sha256": "4b8a525c…",      // the agent's live config when it answered
    "caller_config_sha256": "…",              // the caller's voice + endpointing
    "caller_plan_sha256": "…",                // the exact questions, in order
    "cases": ["price-premium", "contract", "support-hours"],
    "greeting_transcript": "thanks for calling Northwind internet how can I help you today",
    "greeting_timed_out": false,
    "turns": [
      {
        "index": 2,
        "kind": "case",
        "text": "Is there a fee if I cancel my service?",   // what we actually said
        "case_id": "cancellation-fee",
        "expect_keywords": ["no", "cancellation"],
        "spoken": true,
        "transcript": "there is no cancellation fee",       // what they actually said
        "answer_verified": true,        // NOT scored — see below
        "reply_timed_out": false
      }
      // … one per turn
    ]
  },

  "recording": {
    "url": "https://…/bench-vapi-20260730-183425/call-003.wav",
    "sha256": "d4af76307ddeedcb…",     // verify before you trust the bytes
    "bytes": 1317804,
    "source": "recording_raw.wav"      // the carrier tape, before our resample
  },

  "cost": {
    "vendor_call_id": "…",             // their id for this call, for your own audit
    "cost": 0.0673,
    "currency": "USD",
    "duration_s": 44.0,
    "billed_s": null,                  // set where a platform bills a minimum
    "source": "GET /call .cost",       // the endpoint and field, so it is re-fetchable
    "notes": ["…"]                     // caveats that qualify the figure
  }
}
```

Three fields carry more weight than their size suggests:

**`channel_map`** decides which side of the stereo tape is whose. Getting it backwards produces plausible-looking numbers that are wrong in both directions, and it was wrong once here — the value is `{"near": 1, "far": 0}` because a probe proved it, not because it was assumed.

**`answer_verified`** is a keyword check on the transcript, published as context. It is **not** an accuracy score and nothing on the leaderboard depends on it. A turn where the agent answered the wrong question is still a valid latency measurement.

**`vad_disagreement_signed_ms`** keeps the sign because the two directions are not equally dangerous. Our detector firing *earlier* than the cross-check risks under-reporting latency; firing later is conservative. The discard rule is asymmetric for that reason.

## What is not here

**No audio.** Every recording is referenced, never shipped:

- the tape is the carrier's, unmodified, at whatever rate it was written
- the analyzer works on that tape resampled to 8 kHz — a deterministic step you can reproduce, and the reason `recording.source` names the raw file rather than the resampled one
- `sha256` covers the bytes at the URL, so tampering is detectable

`tools/verify_run.py` does all of this: fetch, checksum, resample, re-measure, diff.

## What's redacted

Only **phone numbers** are scrubbed, and only ours. The sentinel is `***REDACTED***`.

A phone number is an attack surface with a metered cost — anyone can call a benched agent and burn its credits — so no number that reaches a live agent appears in this repo.

Everything else is verbatim, including:

```
assistant_id, agent_id, llm_id, call_control_id, call_sid, vendor_call_id,
every sha256 receipt, every transcript, every flag, every discard reason
```

Agent and assistant ids are **not** secrets: they are inert without an API key, and they are part of the config receipt that gives a published number its provenance. Scrubbing them would weaken the receipt to protect nothing. `call_control_id` and `vendor_call_id` are how you correlate a call here with the platform's own record of it.

### If you publish your own runs, read this first

A local run also writes `runs/<run_id>/applied_config.json` — the platform's live
config echoed verbatim, which is what the receipt's sha256 is computed over.
**Some platforms put the account holder's name and email in that response.**
ElevenLabs returns `creator_name` and `creator_email`; others may add fields
without warning.

Nothing here exports that file — `tools/export_snapshot.py` never reads it, and
`runs/` is gitignored — which is why the published artifacts carry only
`vendor_config_sha256` and the named `vendor_defaults_used` fields rather than
the raw echo. If you build your own publishing step, do not shortcut that:
copying `applied_config.json` into a public repo is the obvious way to leak your
own contact details. Scrubbing it after the fact does not help either, since the
sha256 is computed over the unscrubbed bytes.

## Reproducing any single number

```bash
.venv/bin/python tools/verify_run.py <run_id>
```

Or by hand, for one call:

1. **Fetch the tape.** `recording.url` from the artifact. Check it against `recording.sha256`; if it differs, stop — the bytes are not the evidence the number came from.
2. **Resample to 8 kHz.** Per channel, PCM_16. This is what the analyzer reads.
3. **Re-measure.** Put the resampled file as `recording.wav` in a directory with `metadata` written out as `metadata.json`, then run the analyzer over it. `metadata.json` is required: without `channel_map` the analyzer cannot tell the two sides apart.
4. **Diff** your per-turn `ttfab_onset_ms` against `result.turns[].ttfab_onset_ms`.

The analyzer is deterministic and reads no clock, so a matching input gives a matching number. At the time of publishing, all 2,078 turns on the board re-derive exactly — both the 2026-07-31 generation and the 2026-07-30 runs pooled with it, the latter measured by an analyzer one version newer than the one that first published them.
